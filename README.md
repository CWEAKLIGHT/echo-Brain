# ECHO

ECHO 是一款使用 Godot 4.7.2 Standard 与 GDScript 开发的 2D 回合制战术游戏原型。

## 项目状态

- **里程碑**：Prototype 0.1，可运行战斗切片
- **引擎版本**：Godot 4.7.2 Standard
- **桌面开发与验证平台**：Windows 10/11（64 位）
- **目标画面**：1280 × 720，横向布局
- **移动端方向**：Android 横屏；本阶段优先完成 Windows 桌面导入与玩法验证
- **技能组版本**：誓守者 V2（裁决印记 / 誓盾庇护 / 绝对守护 + 被动不屈誓约）
- **验证状态**：已在 Godot 4.7.2 中完成导入、十五个测试套件与主场景无头运行（2026-11-25，582 条断言 0 失败）；Windows 交互与画面、Android 导出仍待人工验证

本仓库是 ECHO 的独立项目，与「拾光」完全分离。

## Windows 导入与运行

1. 安装 **Godot 4.7.2 Standard** 的 Windows x86_64 版本。不要下载 .NET 版本。
2. 在 GitHub 仓库页面下载 `main` 分支 ZIP，并完整解压到普通文件夹。
3. 启动 Godot，在项目管理器中点击 **导入（Import）**。
4. 选择解压目录中的 `project.godot` 文件，点击导入并编辑。
5. 等待首次资源扫描完成，然后按 **F5** 运行主场景。

也可以直接下载当前主线：

- [下载 main 分支 ZIP](https://github.com/qingxu443-dev/echo-game/archive/refs/heads/main.zip)
- [打开 ECHO GitHub 仓库](https://github.com/qingxu443-dev/echo-game/tree/main)

首次运行不需要 Android 导出模板，也不需要 Godot .NET 版本。

## 当前可玩的战斗内容

- 瑟弗林（守誓者）与 8 × 8 正交网格战场。
- 三种敌人：先锋、神射手、区域术士。
- 每回合 3 点 AP；移动消耗 1 AP，最多移动两格。瑟弗林的普通攻击已从玩家操作界面移除，输出依赖技能与被动。
- 敌人意图在玩家回合开始时公开，并按固定顺序执行。
- 誓守者 V2 技能组：
  - **裁决印记**：1 AP，对 1–4 格内单个敌人造成 DEF×0.8 物理伤害并施加印记。
  - **誓盾庇护**：1 AP，为瑟弗林与两格内友军施加 DEF 系护盾。
  - **绝对守护**：2 AP + 5 点终极能量，嘲讽并反击。
  - **不屈誓约**（被动）：敌方主动攻击命中瑟弗林时获得守誓，最多三层；誓盾庇护消耗全部层数。
  - **猎人通灵**：0 AP，任意敌人现身一击，冷却 2 回合；技能栏显示余泡泡图标。
- 技能按钮、AP 消耗、终极能量门槛、目标选择、目标范围提示和状态标识（护盾、绝对守护、裁决印记）。
- 鼠标操作与键盘技能快捷键。

## 关卡与结算

战斗按固定关卡配置推进，关卡数据位于 `scripts/battle/level_catalog.gd`：

| 关卡 | 敌人 | 战术考点 |
|---|---|---|
| 第一课 · 蓄力 | 一名先锋（正前方两格） | 先锋锁定脚下的格子蓄力，移动一格即可规避 |
| 第二课 · 射线 | 一名神射手（隔整条边） | 神射手只在 3–6 格直线上开火，贴近到最小射程内即可逼其待机 |
| 第三课 · 混编 | 先锋 + 区域术士 + 神射手，带地形障碍 | 三种威胁叠加，目标优先级决定走向 |

- 关卡初始布阵、敌人配置与障碍布局全部固定，不使用随机站位。
- 战斗结束后弹出结算面板，显示关卡、回合数、造成伤害、承受伤害、击败敌人数与剩余生命。
- 结算面板提供「重开本关」；胜利时提供「下一关」，打完最后一关后变为「从头开始」。

## 视线规则

瑟弗林的指向技能（裁决印记）要求目标与自身处于**同一行、同一列或对角直线**上，且路径无遮挡：

- 斜角相邻或斜角方向上的目标可以正常命中。
- 路径中间若有障碍或单位阻挡，判定失败。
- 非对齐的偏移（如横向差 2、纵向差 1）没有直线可言，判定失败。

敌方行为不受此规则影响：神射手仍只沿正交直线开火，先锋的蓄力也仍是正交方向——这两条线是玩家需要读取的预告信息。

## 桌面操作

| 操作 | 输入 |
|---|---|
| 移动 | 鼠标左键点击可到达的格子 |
| 裁决印记 | 点击技能按钮或按 `1`，再点击合法敌人 |
| 誓盾庇护 | 点击技能按钮，或按数字键 `2` |
| 绝对守护 | 点击技能按钮，或按数字键 `3`（需 5 点终极能量） |
| 猎人通灵 | 点击技能按钮或按 `4`，再点击合法敌人 |
| 取消目标选择 | `Esc` 或鼠标右键 |
| 结束回合 | 点击「结束回合」、`Enter` 或空格键 |

数字键 `1–4` 对应当前技能栏顺序。未选择技能时，点击敌人不会发动瑟弗林攻击；自身技能按下后立即施放，目标技能需要再点击战场上的敌人确认。敌方单位的普通攻击机制不受影响。

## 自动化测试

在项目根目录、Godot 4.7.2 Standard 环境中，一条命令跑完全部套件并汇总：

```sh
tests/run_all.sh          # bash
tests\run_all.bat         # Windows：双击，或 cmd 中执行
```

输出形如：

```
test_battle_controller                 162 ok
...
-----
suites=15 assertions=582 failures=0 broken=0
```

退出码为 0 仅当所有套件 `failures=0` 且无一崩溃。Windows 若未把 Godot 加入 PATH，用参数指定可执行文件：

```powershell
.\tests\run_all.ps1 -Godot "C:\Godot\Godot_v4.7.2-stable_win64_console.exe"
```

单独跑一个套件：

```sh
godot --headless --path . --script res://tests/test_core_rules.gd
```

每个套件结束时打印一行机器可读结果 `RESULT <名称> assertions=<n> failures=<n>`。

当前基线为 **十五个套件、582 条断言、0 失败**，逐套件明细见 `docs/engineering/BASELINE.md`。后续任何改动都应重跑并以零失败为准；headless 测试不能替代 F5 主场景的鼠标、键盘和画面检查。

## 当前边界

- 主场景直接进入第一关战斗，没有标题菜单或关卡选择界面；关卡切换只通过结算面板的「下一关」。
- 当前战斗界面仍是功能原型表现，不是最终美术。
- 伙伴的独立行动、章节流程、局外成长、经济和存档不属于当前 Prototype 0.1 范围。
- Android 导出和设备表现尚未验证。
- 所有技能与敌人数值仍是待实际对局验证的原型基线。

## 仓库结构

- `docs/`：设计规范、项目状态和验证清单
- `scenes/main/`：主入口场景
- `scripts/battle/`：战斗规则、技能效果、意图与状态系统、关卡数据
- `scripts/actors/`：战斗单位数据
- `scripts/ui/`：原型战斗界面
- `tests/`：规则、控制器、技能效果、关卡数据和 UI 集成测试

ECHO 与「拾光」项目严格隔离。不要将拾光代码、配置或数据加入本仓库。
